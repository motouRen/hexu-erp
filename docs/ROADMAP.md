# 路线图与开源发布计划

## v0.1 当前交付

源码、登录与角色、商品、门店、渠道、库存余额与流水、占库订单、全额收款整单发货、取消、按行退货退款、CSV、演示初始化、中文界面、迁移、业务测试、CI 和设计文档。

验收以可实际操作的本地闭环为准。平台自动拉单、在线支付、正式会计能力不计入 v0.1 完成范围。

## v0.3 渠道自动化

先选一个实际平台，获得商家授权和官方接口资格后接入。交付连接器接口、事件去重、游标、重试、异常订单队列、平台签名验证、库存同步与观测。平台“已付款但缺货”必须保留待处理订单；退款申请与实际到账分状态。CSV 作为人工补录入口继续保留。

## 后续按需求选择

采购订单与供应商应付、批次和效期、促销优惠与运费分摊、分仓分批发货、发票及会计对接、POS 扫码、会员、盘点移动端。每项都应先明确业务口径和验收，再扩展数据模型。

AI 方向可优先做只读查询、异常解释和补货建议；提交订单、扣库、退款仍调用受权限与事务保护的业务接口。不能让模型直接修改库存或资金表。

## 对外发布前

1. 确定公开名称及仓库归属，检查重名与项目标识。
2. 在空环境验证 README 启动；在 PostgreSQL 跑完并发测试。
3. 检查 Git 跟踪范围，仅包含源代码、许可证、文档与虚构示例。
4. 开启私密漏洞报告，补充维护者与贡献说明。
5. 创建公开仓库、推送源码、发布 v0.1.0 标签与真实截图。

发布目标：`motouRen/hexu-erp` 公开仓库。源码已经完成本地验证；远程发布状态以 GitHub 仓库和工作流实际结果为准。
