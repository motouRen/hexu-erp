这是 2026-11-09 启动的临时在线演示。仅在演示电脑、应用服务与连接进程持续运行期间有效；停机后会失效，重新启动连接时地址可能变化。它不是承诺长期可用的托管站点。Cloudflare 官方也将 [Quick Tunnels](https://developers.cloudflare.com/tunnel/get-started/quick-tunnels/) 定义为测试开发用途，没有持续在线保证。固定域名与长期部署需要独立服务器和相应配置。

## 公开演示账号

| 账号 | 密码 | 门店与权限 |

| `demo` | `HexuDemo2026!` | 两个演示门店，只读，可查看和导出 |

账号均无后台管理和成员授权权限。所有数据为虚构，收退款是人工登记，不触发实际扣款或转账。不要录入真实客户、密码或交易信息。共享演示账套中的操作会影响其他访问者看到的数据。

## 建议体验顺序

1. 用 `demo` 查看概览、订单条件筛选、分页及导出。
2. 用 `demo_operator` 在“库存单据”创建一张门店调拨单，保存草稿，再确认过账；查看两端库存和流水。
3. 用同一操作员创建盘点单，填写实盘数量并提交。退出后用 `demo_reviewer` 打开该单，核对差异并审批。
4. 用 `demo_store` 查看门店筛选，只有上海静安店。即使手工拼接杭州门店的查询或写入请求，也会被服务端拒绝。

如果盘点期间该商品发生其他库存业务，审批会提示重新盘点。这是版本保护规则，不是演示故障。

## 本地复现

```powershell
.\demo.ps1
```

打开 <http://127.0.0.1:8767/>，账号同上。脚本仅建立独立演示账套，不重置普通数据库，不创建公开管理员密码。Mac/Linux 可按 README 建立虚拟环境，安装 `requirements-demo.txt`，设置 `ERP_DEMO_MODE=1` 后迁移、初始化，再用 Waitress 单工作线程启动。

普通 `start.ps1` 仍使用正常本地账套和随机管理员密码。生产模式默认强制 PostgreSQL；仅隔离演示允许单线程 SQLite。源代码包不包含演示数据库、私有密钥、运行日志或浏览器登录状态。

## 临时公网地址复现

Windows 可运行 `./public-demo.ps1`。它准备独立演示账套，从 Cloudflare 官方发行地址下载连接程序（放入被忽略的 `.tools/`），以隐藏后台进程运行，并打印本次临时 HTTPS 地址。默认只将演示应用的回环端口 8768 接入，不暴露普通账套服务。端口已占用时可用 `-Port 8770`。

程序和连接进程必须保持运行；当前运行信息保存在被忽略的 `output/public-demo.json`，只包含本地进程号、端口和公开地址，不含管理员密码。每次创建连接可能得到不同域名，需相应更新对外分享的地址。长期运行请采用固定域名及独立服务器。
